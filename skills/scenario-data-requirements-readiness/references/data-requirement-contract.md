# 数据需求与准备度契约

## 任务—数据需求矩阵字段

| 字段 | 说明 |
|---|---|
| task_id | 对应 Agent 任务 |
| decision_or_action | 数据支撑的判断或动作 |
| required_fact | 需要确认的业务事实 |
| data_domain | 业务、财务、IT 技术或其他领域，可多选 |
| data_role | 主数据、事实、规则配置、指标、结果、日志、审计等 |
| data_object | 所需数据对象 |
| required_elements | 必需字段或指标 |
| granularity | 一条记录代表什么 |
| time_and_version | 时间范围、时点、期间和版本要求 |
| quality_threshold | 完整性、准确性、及时性等最低标准 |
| permission | 访问角色、敏感等级和授权条件 |
| source_location | 系统、数据集、表、字段或接口 |
| owner | 数据责任人 |
| readiness | 可用、需清洗、缺映射、缺权限、时效不足、人工记录、缺失 |
| task_impact | 缺失后影响哪些判断和动作 |
| remediation | 补充、替代、样本验证或范围调整 |

## 三类数据判断提示

### 业务数据

描述业务对象、事件、过程和状态，例如客户、项目、合同、订单、工程活动、进度和变更。

### 财务数据

描述预算、成本、收入、资金、会计、税务和财务结果。合同金额、付款计划等可同时带业务和财务标签。

### IT 技术数据

支撑数据获取、运行和审计，例如系统标识、接口结构、表字段元数据、更新时间、任务日志、调用日志、权限配置和运行状态。

## 准备度结论

- `ready`：已授权、可访问、质量和时效满足要求。
- `conditional`：需要清洗、转换、映射或补充确认。
- `sample-only`：只有脱敏样本，可用于验证，不能声称生产就绪。
- `blocked`：缺数据、缺权限、缺责任人或关键质量不满足。

准备度必须按具体 Agent 任务判断。同一数据可以支持任务 A，同时阻断任务 B。
