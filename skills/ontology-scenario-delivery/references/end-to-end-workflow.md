# 端到端建设链路

## 阶段与准入

| 阶段 | 核心问题 | 必备产物 | 进入下一阶段的条件 |
|---|---|---|---|
| 0 场景快速扫描 | 谁遇到什么问题 | 场景摘要、事实与假设 | 用户、问题、目标结果可描述 |
| 1 本体适用性初判 | 本体是否值得投入 | 适配结论、垂直切片 | 语义、关系、规则或追溯复杂度支持投入 |
| 2 智能体作用识别 | Agent 在场景中做什么 | 任务清单、分工、风险和指标 | Agent、确定性系统、人工边界明确 |
| 3 场景完整梳理 | 完整业务闭环是什么 | 场景说明、流程、判断、动作、异常 | 场景开始、结束、责任和验收明确 |
| 4 数据需求与准备度 | 三类数据需要什么、是否可用 | 任务数据矩阵、物理来源、缺口 | 关键判断的数据需求和阻断项明确 |
| 5 场景知识结构 | 知识与证据在哪里 | 来源、专家、案例、资产和冲突台账 | 关键知识有来源或明确待确认人 |
| 6 场景语义模型 | 数据和知识准确表示什么 | 对象、术语、关系、约束、规则、动作和目标 | Agent 任务所需语义完整 |
| 7 概念模型 | 业务如何审查整体模型 | 八类业务视图、模型元素清单 | 业务专家可理解并确认 |
| 8 逻辑本体 | 系统如何存储和计算 | 类、属性、关系、约束、查询和动作契约 | 模型可解析且候选内容已隔离 |
| 9 数据到本体映射 | 数据如何进入类和实例 | 类/属性/关系映射、实例规则和样例 | 样本可实例化且可追溯 |
| 10 技术验证 | 模型技术上是否成立 | 语法、结构、逻辑、约束和查询报告 | 技术阻断项关闭 |
| 11 业务验证 | 能否回答真实业务问题 | 专家评审、黄金/边界/异常/权限用例 | 关键任务用例通过 |
| 12 资产登记与发布 | 怎样形成正式版本 | 登记卡、版本、依赖、灰度和回滚 | 责任、权限、版本和回滚明确 |
| 13 运行服务 | Agent 怎样调用 | 服务契约、最小加载、调用审计 | 响应含版本、来源和证据 |
| 14 反馈演进 | 怎样持续修正 | 反馈台账、变更单、回归和新版本 | 变更完成影响分析和回归 |

## 关键返回条件

- 第 2 阶段发现 Agent 价值不足：返回轻量查询、规则或工作流方案。
- 第 3 阶段发现本体只支撑局部任务：缩小到最小子本体并重做适配结论。
- 第 4 阶段发现关键数据不可得：冻结依赖该数据的任务或设计样本验证，不继续假设数据就绪。
- 第 5 阶段出现知识冲突：进入专家裁决，冲突条目不得进入已确认语义。
- 第 6—9 阶段发现语义缺口：返回知识结构或场景梳理，不在形式模型中补造业务规则。
- 第 10—11 阶段出现阻断缺陷：退回相应模型阶段，修订后执行回归。
- 第 13—14 阶段出现新术语、未知对象、规则失效或数据漂移：建立变更单并保留原生产版本。

## 输入成熟度与可交付范围

| 已有输入 | 可以交付 | 必须标记的限制 |
|---|---|---|
| 只有场景描述 | 场景卡、适配初判、Agent 候选任务、资料清单 | 所有模型内容为候选 |
| 增加制度和业务材料 | 知识结构、语义候选、29 类建模语句 | 仍需专家裁决和数据核验 |
| 增加数据字典和接口资料 | 数据需求、物理来源、语义定义、概念模型 | 是否可实例化取决于样本和权限 |
| 增加真实样本 | 实例规则、黄金用例、技术和业务验证 | 结论只覆盖当前样本边界 |
| 完成专家和系统确认 | 正式版本、服务契约、发布与回滚 | 运行后继续监控变化 |
