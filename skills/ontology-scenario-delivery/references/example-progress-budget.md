# 通用示例：进度变化与预算影响

本示例只说明产物怎样衔接，所有对象、规则、系统和指标都需要在真实企业场景中重新确认。

## 场景与 Agent 任务

场景目标：识别工程进度变化可能产生的预算影响，并向有权角色提供可追溯的调整建议。

Agent 候选任务：

- 识别进度变化类型和影响范围。
- 关联可能受影响的预算事项。
- 引用适用规则形成影响说明。
- 生成调整建议并在高风险条件下转人工确认。

确定性系统负责日期、金额和版本等精确计算；业务人员负责规则确认、重大调整审批和最终版本发布。

## 数据需求

- 业务数据：项目、WBS、工程活动、计划与实际进度、变更事件、合同或工程量。
- 财务数据：预算事项、预算版本、预计与实际成本、资金计划。
- IT 技术数据：系统和接口标识、字段结构、数据更新时间、权限和调用审计。

在数据准备度阶段定位真实系统、表、字段和接口，并判断标识、版本、质量和权限是否满足。

## 场景知识结构

- 进度变更和预算调整制度。
- 业务流程、表单和审批记录。
- 数据字典、接口说明和已有映射。
- 历史变更案例和专家判断。
- 已有项目、预算和权限语义资产。

每项来源登记版本、责任、适用范围和证据位置。

## 场景语义模型

- 对象：项目、WBS、工程活动、进度变更事件、预算事项、预算版本。
- 关系：项目包含WBS、WBS包含活动、变更影响活动、活动关联预算事项、调整产生预算版本。
- 分类：进度变更按内容、原因、影响程度和处理状态分别分类。
- 约束：已确认变更才能进入正式影响分析；版本发布需要授权和生效时间。
- 规则：根据影响范围、阈值、版本状态和审批要求形成判断。
- 动作：请求影响测算、生成调整建议、发起审核、发布受控版本。
- 目标：变化及时进入影响分析，判断可追溯，未经授权的版本不得发布。

## 概念与逻辑模型

概念模型分别展示对象关系、分类继承、规则决策表、状态变化、动作权限和目标路径。业务确认后，逻辑模型生成类、属性、对象关系、词汇、SHACL约束和查询模板。

## 数据到本体映射

物理字段已经在数据准备度阶段定位，本阶段建立：

- 一条工程活动记录 → `EngineeringActivity` 类实例。
- 活动业务标识 → 实例 URI 和标识属性。
- 实际完成日期 → `actualFinishDate` 属性。
- 项目标识关联 → `belongsToProject` 对象关系。
- 变更状态代码 → 统一状态概念。

实例同时记录来源记录、数据时间、数据版本和映射版本。

## 验证与运行

黄金用例输入一条真实或脱敏的进度变化，定义预期影响对象、规则路径、调整建议、人工介入和最终状态。运行时记录使用的本体版本、数据来源、规则、判断、动作和业务结果；新术语、未知关系、错误规则或数据漂移进入变更流程。
